# 証券実績

「配当 → 証券実績」で、証券会社の原資料から確認した円建て受取を別枠で表示する。
受取合計には **配当金・貸株配当金相当額・貸株金利** の3区分を含める。
銀行への自動振替、既存のCSV入金、手入力の受取記録、将来予測とは合算しない。

- 年別の合計と内訳、対象年の月別・銘柄別・個別明細、出典の資料名とページ／行を表示。
- 未確認期間は `—`。確認済みで受取がない期間は0。一部期間は明示し、通年実績と誤認させない。
- PDFの四半期報告書では営業日と四半期の範囲を区別する。CSVは指定検索期間を対象範囲とする。
- 金額は原資料の受取・入金欄。税額を逆算したり、貸株収入を普通配当へ変換しない。
- CSVに名義がない場合、原資料との照合根拠と確認できた口座範囲を資料の注記に残す。

## 保存と持ち込み

`broker-receipts-core.js` の検証済みJSONを `asset_compass_broker_receipts_v1` に保存する。
既存の資産・受取記録の保存キーには触れない。currentとpreviousは単一の書き込みで更新し、
同一明細IDは再取込時に追加しない。金額などの相違は上書きせず停止する。
新しい原資料から作るパケットでは、重複期間を照合して既存の明細IDに出典を追加する。
同日・同額でも異なる受取や税区分の明細は別IDを保持する。日付と金額だけでは重複判定しない。

画面からJSONの取込・書出し・直前状態への復元が可能。普段の端末へ渡すファイルは、
`scripts/create-broker-handoff.cjs` でJSONを標準入力から受け、**公開リポジトリ外**に作成する。
ハンドオフのHTMLは年別・全明細のオフライン確認とJSONの保存にも使える。
gzipのURL fragmentはページ到着直後に削除し、展開サイズを制限する。
個人データをサーバーに送信するAPIはない。CSPのconnect-srcもnone。
**個人の明細・金額・口座・反映ファイルを公開リポジトリへ追加しない。**

## 検証

`node --test tests/broker-receipts.test.cjs` で区分別合計・確認範囲・重複・競合・書込失敗を確認。
`tests/broker-receipts-browser.py` は架空データのみで取込、再読込、別枠表示、プライバシーを確認する。
