# 資産コンパス 統合版

入口は `unified.html`。トップの `index.html` もここに転送します。旧 `app.html`、`app-v3.html`、配当各画面、`mf-assets/` はそのまま利用できます。

## 画面

下部のSVGアイコンでホーム・資産・持ち株・配当・設定を切り替えます。資産内は全体像・目的別・資産一覧・名義口座、配当内は10年推移・受取記録・CSV入金・配当予測、設定内は取込・保存・相談に分かれます。

## データの扱い

既存エンジンを同一オリジンの保持型フレームで読み込む統合です。画面ごとの保存方式と金融計算は作り直していません。ホームの資産数値は income-policy 適用後の AssetCore.summary を読み取り専用で参照します。詳細の入力途中の内容や配当の全解除状態を画面切替で初期化しません。

資産総額と持ち株評価額は重複する可能性があるため加算しません。CSV実績と登録済み受取配当も加算せず、設定で集計元を選びます。登録済み受取配当はJPY・当年・税引後判明分のみ。外貨、未来日、不明額を円のゼロ円として加算しません。10年配当は現在株数換算の参考値であり、実入金とは別です。

持ち株・受取配当のlocalStorageキーと、資産管理のIndexedDB（asset-compass-v1/workspace/data）は変更しません。統合設定だけを kouheim_suite_* に保存します。自動移行・自動上書き・新たな外部送信はありません。資産管理の「今回のみ」設定も維持するため、必要な場合は保存を有効にしてください。バックアップは各機能で個別に行います。端末間の自動同期はありません。

金額非表示時、ホームの金額を伏せ、詳細フレーム全体を非表示・inert・aria-hiddenにします。表やグラフからの漏れを防ぎ、表示を戻せば作業を再開できます。これは画面の表示保護であり、端末保存の暗号化ではありません。

## 目的別ポートフォリオ

`unified.html#assets/purposes`（資産 → 目的別）は、既存の保有資産データを直接集計します。Money Forwardの保有資産CSV・見出し付きの表を既存の取込画面で取り込むと、資産ごと／名義・口座ごとに目的を設定できます。ログインによる自動取得ではありません。入出金・資産推移だけでは目的別の内訳を生成しません。

分類は `purposePortfolio` として既存の資産ワークスペース・復元用バックアップに保存します。元の金融計算・保存設定・データベースのキーは維持します。同じ保有資産キー（名義・口座・銘柄・税区分・重複出現順）を再取り込みすると分類を引き継ぎます。名称や口座表記を変えた資産は未分類です。目的を削除した資産も未分類に戻り、資産合計は変わりません。分類は重複せず、表示範囲は名義フィルターに従います。

金額は現在の保有資産から読み取り、分類用の別残高は持ちません。評価損益は取得額が判明する資産のみで計算し、その件数を表示します。残高日が混在する場合は日付範囲を表示します。前日比・年初来比は保有資産一覧だけでは算出しません。目的名・期間・色の編集は保存まで反映せず、端末保存のオン／オフとデモの保存禁止も既存動作に従います。

## 検証

`node --test tests/*.test.cjs` で既存回帰と統合アダプターを検証します。`python tests/suite-browser.py` は架空データで起動・下部ナビ・全サブ画面・下書き保持・10年配当・空選択・金額非表示・320〜1440pxを検証します。`python tests/suite-purpose-browser.py` は架空の保有資産の取込・目的分類・再取込・保存再読み込み・デモ隔離・320〜1440pxを検証します。GitHub Actions の Unified app verification がブラウザのスクリーンショットとJSON結果を保存します。

ウェブアプリ用manifestとiOSメタ情報を用意しています。サービスワーカーを追加していないため、オフライン動作は保証しません。
