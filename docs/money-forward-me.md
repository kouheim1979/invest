# Money Forward ME → 資産コンパス

ChatGPTの公式ME連携で取得したデータを、`me-import.html` から既存のIndexedDBワークスペースへ反映します。MEの認証情報をアプリに渡す機能や、常時自動同期はありません。

1. MEの残高と個別保有資産を取得し、資産区分別の合計を照合する。
2. 次の形式のJSONを **公開リポジトリの外** で準備する。明細や実際の金額をコード、コミット、Issue、PRへ記載しない。
3. `node scripts/create-me-handoff.cjs /absolute/private/path/me-handoff.html < /absolute/private/path/packet.json` で本人用の反映ファイルを作る。作成されたファイルにも金融データが含まれるため、公開配布しない。
4. 本人が普段のブラウザで反映ファイルのボタンを開き、「この端末へ反映する」を押す。

```json
{
  "format": "asset-compass-me/v1",
  "currency": "JPY",
  "asOf": "YYYY-MM-DD",
  "retrievedAt": "ISO-8601取得日時",
  "categories": [["資産区分", 0]],
  "holdings": [{
    "institution_name": "金融機関名",
    "account_name": "口座名",
    "asset_category": "資産区分",
    "name": "資産名",
    "current_value": 0
  }]
}
```

反映リンクのフラグメントはHTTPリクエストへ送られません。反映画面では即座にURLから除去し、通信を禁止するCSPの下でローカル展開・照合します。リンクを知る人はデータを読めるため、リンク自体は公開しないでください。

反映では保有資産をMEの完全な残高一覧に入れ替えます。負債は取得時点の別枠表示とし、総資産や目的別分類へ加算しません。マイナスのポイントは資産残高の調整として維持します。同一金融機関・口座名・資産区分・資産名の明細は合算し、MEが返さない口座IDや税区分は推定しません。

名義設定・入出金・目的設定・過去の履歴は保持します。同じ日付の履歴はMEの資産総額で更新します。個別名義・目的は同一資産と明確に照合できる分だけ引き継ぎます。数量・取得額・配当単価・税区分は更新済みと誤認させないよう未設定にし、更新前ワークスペース全体を `workspace/me-previous` へ同じトランザクションで退避します。独立した「持ち株」のデータは変更しません。

MEには資金の使い道が含まれないため、初めて取り込む未分類の資産へ仮の目的を設定します。すでに取り込んだME資産も、資産画面の再読み込みで一度だけ移行します。既存の手動分類を優先し、分類後に手動で「未分類」へ戻した資産は、再読み込みや再取込でも未分類のまま保持します。

| 対象 | 仮分類 |
| --- | --- |
| 子ども名義の資産 | 子ども名義資金（用途は未指定） |
| 年金 | 老後資金 |
| 株・投資信託・債券・暗号資産・証拠金 | 資産形成 |
| 預金・現金・MRF | 預金・待機資金（使途は未指定） |
| 電子マネー・通常のポイント | 日常支払い |
| マイル・マイレージ | 旅行ポイント |
| その他 | その他資産（用途を確認） |

名義は既存の持ち株画面の口座コードに合わせ、明確なOTS・OKS・MIK・RINだけを補完します。個別名義や口座名義が設定済みなら上書きせず、金融機関名だけからは推測しません。教育費・生活防衛費など具体的な使途は決めつけず、仮分類であることを目的別画面と各明細に表示します。実際の使い道は一覧の選択欄から変更できます。

直前の反映は反映画面から取り消せます。取消はワークスペース全体を反映直前へ戻すため、その後の編集も戻ります。保存をオフにする操作や全データ削除では退避データも消します。同一パケットは再追加せず、新しい取得日時のデータを古いリンクで巻き戻さないようにしています。

`node --test tests/*.test.cjs` で照合、符号、重複、引継ぎ、欠損、再取込、既存計算を検証します。
